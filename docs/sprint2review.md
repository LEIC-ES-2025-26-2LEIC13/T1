# Sprint 2 Review

## Did well

- Implementing a lot of features that were planned for the sprint as well refining the existing codebase, promoting code reusability and maintainability.
- Accomplished all goals planned for the sprint.

## Do differently

- Better time estimation for the effort required for certain PBIs. Some were heavily underestimated, which led to a lot of work being left for the end of the sprint, which is not ideal.
- Creating consistent code patterns from the start of a feature implementation to avoid future refactors.

## Puzzles

- NoSQL database choice probably wasn't the right choice from the beginning, due to the need of maintaining consistency between information across several collections/subcollections. This led to a very slow and careful database logic implementation process and makes the database fragile to small changes in its logic.

## Final Thoughts

- Overall, the sprint was a success, with all the planned features being implemented and a significant improvement in the codebase structure and design. However, there were some challenges along the way, particularly with time estimation and initial database design.

## Teamwork Assessment

- The work was evenly distributed accross the team members.
- Since the tasks were very interdependent, we communicated a lot with each other, so everyone was aboard with the ongoing development process.
